This project involved building an embeddable OLTP engine whose external surface mimics SQLite—supporting tables, secondary indexes, joins, foreign-key cascades, and uniqueness constraints—while internally representing all data as CRDTs (Conflict-Free Replicated Data Types) throughout, enabling multiple writers to mutate locally without any coordination, with merges converging deterministically and invariants surviving under all conditions. The core technical challenge was identifying which relational invariants are natively CRDT-expressible (such as set membership, last-writer-wins fields, and monotonic counters), which require lattice-respecting encoding (multi-value registers for conflicting cell writes and observed-remove sets for membership under concurrent insert/delete), and which fundamentally demand a coordination protocol (uniqueness constraints via escrow or reservation protocols, and foreign-key existence under deletion). The engine implements a full SQL surface including CREATE TABLE with primary keys and secondary indexes, INSERT/UPDATE/DELETE operations across N concurrent peers without a coordinator, and deterministic reads that return merged results consistently regardless of the order in which peer updates were applied. Foreign-key cascade behavior under partition was carefully designed with documented and defended semantics, while uniqueness constraints were enforced through an explicit escrow protocol—acknowledging that pure CRDTs cannot handle this natively. A pairwise sync protocol with bounded metadata ensures eventual convergence, with garbage collection integrated to prevent unbounded vector clocks or version vectors. Stretch capabilities included bitemporal queries (transaction-time and valid-time over merged history), causal reads (monotonic-read and read-your-writes guarantees at the client), and online schema migration under partition—the unsolved final boss of distributed systems. The engine was built with strong type discipline, and the implementation avoided anti-patterns such as server-authoritative conflict resolution, degenerate row-level last-writer-wins, and unbounded metadata growth, instead delivering cell-level conflict resolution, lattice-respecting encodings, and a robust architectural defense of every coordination decision made, ensuring deterministic merged states on all peers even after disconnecting over unreliable networks.

I designed three progressive tasks—ranging from easy to medium to hard—each with programmatic graders that score agent performance on a 0.0–1.0 scale, with the hard task genuinely challenging frontier models through complex transaction patterns and subtle anomaly detection scenarios. A baseline inference script using the OpenAI API client runs the model against the environment, reading credentials from environment variables and producing reproducible baseline scores across all three tasks. The system's architecture includes state management for transaction histories, sensible action spaces (flag, investigate, escalate, or clear), and observation spaces containing transaction metadata, account histories, and risk indicators.
